### 4.3 一句话结论

Nook X 在**"组件化配置面板 + 首页信息密度 + 待办/番茄钟的产品化打磨"**这三件事上比我们成熟（它是个卖了近一年、迭代 25 个版本的付费产品）；我们在**系统能力广度**（系统通知上岛、局域网互传、剪贴板/下载监控、进程级音频 tap（用于可视化，**不是**每 App 音量控制）、锁屏面板群、终端、三档背景可配）和**基础技术路线干净度**（只用系统 Now Playing、零麦克风识别、零账户）上明显领先。要抄的是**信息架构与首页排版**，不要抄它的功能堆料与付费门控。

## 5. 首页（Home）区域专节 —— 它到底怎么排的

> 用户的原话关切：**"首页是否只放音乐 + 日历、日历今日内容怎么展示才不浪费空间"**。以下是读图（图 A / 图 D 的刘海区域放大 3 倍）与版本历史交叉所得的**可见事实**，再给排版建议。

### 5.1 首页不是"只有音乐 + 日历"，而是一条横向密排的多块 strip

从图 D/图 A 的展开态（左 → 右）能辨认出的块，按顺序是：

| 位置 | 块 | 可见内容 | 观感尺寸 |
|---|---|---|---|
| 顶部 | 分类标签 | 两个 pill：`Nook X`（当前）+ `文件暂存`；另有分页器（图标形式） | 一行，很矮 |
| 最左 | 日期 / 农历 + 计时 | 绿色小字 `周五, 9/26`（读作日期行）+ 其下一个**大号橙色数字** `00:14`/`00:40`（计时器）+ 再下一行天气 chip `多云 26°-32°`（带云朵小图标） | 约占首页高度全高，宽度最窄；**大数字是整条上是最大字号** |
| 左中 | 现在播放 | 圆角方形封面 + 歌名（`可惜我是水瓶座`）+ 歌手（`杨千嬅`）+ **当前一句歌词**（`无谓再会要是再会更加心碎…`）+ 进度条（`1:14 / 3:36`），进度条左端有一个小红色图标 | 宽度最大的一块，横向排列而不是上下堆叠 |
| 中右 | 快捷启动 | **2×2 的 4 个应用图标网格**（截图中为 2 个紫色图标 + Chrome + VS Code） | 一块方阵，约等于两块 icon 的宽 |
| 右 | 临时笔记 | 一块小文本卡，两行字（`这是临时笔记~` / `如果有想法，可以在这里记录哦`），右下角两个很小的操作图标 | 与播放块等高，宽度中等 |
| 最右 | 快捷指令 | **两行胶囊**，每行 = 左侧圆形图标 + 右侧指令名（读作 `小红书去水…`、`彩虹原生生成…`） | 竖向两行叠放 |
| 更右 | 镜子 | 圆形摄像头预览 + 下方文字标签 `镜子` | 一个圆 |
| 右端 | 番茄钟 | 圆环 + 文字 `25:00`，环上另有一个橙色小点（状态灯） | 一个圆 |
| 角标 | 智能协作 | 右上角文字 `智能协作`（AI 入口的角标） | 一个标签 |

**要点（对用户疑问的直接回答）**：
1. **首页同时并列 6–8 类块**，不是"音乐 + 日历"两块；日历在首页上**几乎没有独立块**——它被压成了"日期行 + 天气 chip"这种 2 行小信息条（图 D 左端）。
2. **真正的日历界面不在首页**，而在 `日历天气` 这个独立组件面板里（2026.09.15 起"以看板管理，支持按日、周、月显示日历"）。也就是说：**它刻意不让月历占用首页空间**。
3. **没有滚动列表**：首页是一条 strip，块与块左右并列；切换靠顶部 pill 标签/分页器与手势（双指轻扫、拖拽滑动切换分类，2025.12.13），不是纵向滚动。
4. **几乎没有留白**：块的宽度按内容自适应（数字块窄、播放块宽、图标块方），不是等分网格；辅助信息全部缩成小字号 chip（日期、天气、歌手），把大字号的"焦点位"留给计时数字。
5. **块的数量由用户决定**：每个块对应设置页里一张带 ON/OFF 的组件卡（图 A/B 底部一排）——**首页 = 已开启组件的横向拼装**。这是我们最该学的一条结构性设计。

### 5.2 可借鉴的 3 条排版建议（针对我们首页）

1. **日历不进首页做"整屏月历"，压成 2 行信息条**。首页左端放"今天 + 农历 + 下一日程倒计时 + 天气温度"四件事，用 2–3 行小字号 chip 表达；月历/日程详情放到独立 tab（或锁屏面板）。这样省下的横向空间给"现在播放"和"待办"，符合我们已定的"扫一眼就够"定位。
   - **本批结论（2026-09-29，`p2-home-strip`）：部分采用。** "整屏月历不进首页"这半条采用——月历 `StandaloneCalendarView` 本批之后在展开面板**没有入口**（[17](17-nookx-adoption.md) 已知限制 8）；"压成 2 行 chip"这半条**未采用**——用户明确要求"日历的今日内容不能只是一行"，落地为自建的「一行日期头 + hover 展开的日期轮 + 竖向紧凑多行」块（[17](17-nookx-adoption.md) D-09）。建议里的"农历 / 下一日程倒计时 / 天气温度"三件事本批**没做**。
     - **2026-09-29 晚改判（`p2-calendar-row`）**：**"整屏月历不进首页"这半条已反转**——用户拍板「日历单独一排」后，首页下排就是一条全宽日历行（左整月网格 / 右今日清单），即整屏月历**进了首页**（只是不作为 strip 里的一块，见 §4.4 P0-4；[17](17-nookx-adoption.md) 已知限制 8 随之关闭）。"不做 2 行 chip"与"农历 / 倒计时 / 天气没做"两条**不变**。
2. **首页改成"已开启模块的横向 strip"，每块宽度按内容自适应、非等分**。把 `docs/14-module-manifests.md` 的 manifest 直接喂给首页渲染器 + 设置页卡片，实现"Nook X 式：设置里开关 → 首页立刻拼装"。这会把我们已有的模块系统变成用户可见的收益（现在模块系统是工程概念，不是用户可见的产品面）。
   - **本批结论（2026-09-29，`p2-home-strip`）：已落地。** 首页标准分支改为 `HomeStripView`（块来自 manifest 的 `home` 投影 + 宿主内置三块），设置页新增「组件」卡片页——"设置里开关 → 首页立刻拼装"闭环走通（[09](09-features-and-mechanisms.md) §5.8）。**一处差异**：块宽不是完全"按内容自适应"，而是**声明式常量**（模块块由宿主统一给 `180 / 240`，模块不能自定义，[17](17-nookx-adoption.md) 已知限制 7）；富余不拉伸、不足按最小宽度收敛（[17](17-nookx-adoption.md) D-02/D-03）。
3. **字号分层做焦点，别用多行滚动**：焦点位（计时/时间）用最大字号（参考它 00:40 / 25:00 是整条最显眼的元素），辅助信息（日期/天气/歌手）用小字号 chip；歌词**只显示当前 1 行**（必要时加下一行），不要多行滚动吃高度——这与我们 `07d37728`（音乐区块成组顶部对齐）的方向一致，再往前一步就是"减到最少行数、把省下的空间还给别的块"。
   - **本批结论（2026-09-29，`p2-home-strip`）：部分采用。** "不用滚动承载信息"采用——strip **不滚动、不分页**（宁可丢尾部块，[17](17-nookx-adoption.md) D-03）；"歌词只显示当前 1 行"沿用既有做法（本批未改音乐块）。"减到最少行数"**未全线采用**：日历块按用户定稿保留竖向多行（上一条），待办块在块宽 ≥ 220pt 时也画今日清单前 5 条。**2026-09-29 晚注**：那个日历块已整体移出 strip（日历改为独立一排，"今日清单仍是竖向多行"的口径不变，见 §4.4 P0-4）；待办块那条判据不变。
