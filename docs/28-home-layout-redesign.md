## 1. 调研：相似产品的首页是怎么排的

### 1.1 Nook X（闭源；读官方截图 7 张 + 版本历史，见 [16](16-nookx-reference.md) §5.1）

| 维度 | 它的做法 |
|---|---|
| 结构 | **一条横向密排的 strip**，6–8 类块左右并列：日期农历+计时（最窄）→ 现在播放（最宽）→ 快捷启动 2×2 → 临时笔记 → 快捷指令两行胶囊 → 镜子圆 → 番茄钟圆 |
| 宽度 | **按内容自适应**（数字块窄、播放块宽、图标块方），**不是等分网格**；几乎不留白 |
| 高度 | 一条带、块等高；信息用**字号分层**（焦点数字最大、辅助信息缩成小 chip） |
| 溢出 | **不滚动、不分页、不换行**——块数就是用户开着的组件数（设置里每张组件卡 ON/OFF → 首页立刻拼装） |
| 日历 | **首页上没有月历**：被压成"日期行 + 天气 chip"两行小信息条；月历本体在独立组件面板里 |
| 换尺寸 | 宽度/高度可调（版本历史里反复出现"适配隐藏歌名、歌词下的灵动岛宽度""提高宽度高度调整上限"），但没有公开它变了之后块怎么让位 |

**对我们的意义**：它把我们最缺的那条讲透了——**首页 = 已开组件的横向拼装，块宽由内容定**。我们学了一半（组件开关 → 首页拼装已落地），**"块宽由内容定 + 一条流装下所有块"这半条没学**（我们改成了"按带预留高度"）。

### 1.2 Boring Notch（开源，`TheBoredTeam/boring.notch`，读源码）

它的首页**只有两个 tab（Home / Shelf）**，Home = 音乐播放器（封面 + 控制），没有多块分配问题。**不适用**于我们的题面（我们不缺"怎么画播放器"，缺"很多块怎么排"）。

### 1.3 上游 Atoll（我们的基线）

单条横向 strip；块按理想宽不拉伸、不足按最小宽压缩、仍不足**从尾部丢块**（[21](21-strip-honesty.md) 的 `＋N`）。**这正是 `p3-widgets` 要解决的问题**（窄了就越丢越多），但本轮的解法（分两条带 + 固定行高）引入了新的问题。

### 1.4 三种机制的对照

| | 装不下的表现 | 空间利用率 | 尺寸变化时的连续性 |
|---|---|---|---|
| 上游 Atoll | 从尾部**丢块** | 中（不换行） | 差（块一个个消失） |
| **我们现在的分带** | 换行，但**只在各自带内换**；带间不能借空间 | **差**（大块吃整条带高、另一条带挤） | **差**（块在带间整体切换） |
| Nook X 式单条流 | （不换行，靠用户少开） | 高 | —（未公开） |

## 3. 问题归因（4 条，逐条对到代码）

| # | 现象 | 根因 |
|---|---|---|
| P1 | 第一排只有音乐、右半条带空着 | **带是"预留高度"的容器**：主块带的高度先扣掉，紧凑块**没有资格进主块带**（`homeFormFactor == .large` 才进）。只剩音乐时，主块带的剩余横向空间谁也借不到 |
| P2 | 其他块全挤在第二排 | 同上：紧凑块被限制在小组件带里，只能在自己的带内换行 |
| P3 | 第三排只有日历 | 日历是**流之外的全宽行**（[26](26-home-widgets-and-settings.md) §实际交付 10），天然独占一行；且它的开关在「功能」段，不在首页组件节里（用户第 3 点） |
| P4 | 待办块第二行被裁 | 行高是**宿主常量 96pt**（D-12），而待办块内容 = 三环 75pt + 清单行 ≈ 99pt+ |

## 4. 提议的机制：**单条可换行的流（flow）**

一句话：**废掉"两条带"，所有首页块进同一条流；按声明宽度贪心装行，装不下就换行；行高取该行最高块，块不被拉高填满。**

### 4.1 具体规则

1. **块声明两件事**（沿用现有钩子，不新增概念）：
   - 宽度区间 `homeBlockWidth(min:ideal:)`（今天已有：音乐 300/420、镜子 140/160、其余 180/240、统计 220/300）；
   - 高度档 `homeFormFactor`：`.large` → 高 140pt（音乐/镜子：封面 + 文字两行），`.compact` → 高 96pt（其余）。
2. **装行**：按用户顺序（`homeBlockOrder`）从左往右贪婪放入当前行；放不满就留白，放不下就换行（**不丢块**，`＋N` 只在"连一行都放不下"时出现，与 [21](21-strip-honesty.md) 的口径一致）。
3. **行高 = 该行最高块**；块**按自己声明的高度绘制、不拉伸**（音乐块不再把封面拉到 200pt）。
4. **日历行**：仍是一条全宽行，排在流的最后；**它的开关搬到「首页组件」节**（见 §5）。关掉它，省下的高度回流给流（可能多装一行）。
5. **高度不足时的让位顺序**（沿用四档的语义，只是作用对象从"带"变成"行"）：最后一行 → 日历行 → 继续收行 → 空。

### 4.2 对 1041×853 全开的预期效果（按声明宽度估算）

```
行1: [音乐 420] [镜子 160] [待办 180] [前台应用 180]     ≈ 964 + 缝 ≤ 973 ✓
行2: [进度 240] [通知 240] [统计 300]                    ≈ 804 ✓
行3: [日历行 全宽]
```

对照现状（行 1 = 音乐 + 镜子、行 2 = 全部紧凑块 + 统计换行、行 3 = 日历）：**行 1 被填满、紧凑块不再挤在一行、总行数不变**。

### 4.3 代价（如实写）

1. **块高不再统一**：行高随行内最高块变化，视觉上比"等高网格"松散一点——这是 Nook X 那条"按内容自适应"的必然代价。
2. **大块变小**：音乐块从"整条带高（200pt+ 封面）"降到 140pt 档，封面会明显变小（要更大就得给它 `.large` 里再分档）。
3. **要重写布局引擎**：`HomeBandedLayout` / `HomeStripView` / `HomeVerticalFit` 都要动，用例（`HomeStripLayoutTests`）要跟着改口径。**这是本提议最贵的一项**。
4. **顺序语义**：块与日历行同处一条流后，"上移/下移"的作用域要重新说清（现在只对块）。

## 5. 你的第 3 点：日历的开/关进「首页组件」节

与布局方向**无关，可以立刻做**：在组件页「首页组件」节里给**首页日历行**加一行（图标 + 名称 + 开关，读写的还是 `showCalendar` 那一个键），「功能」段里那张重复的卡去掉。

一处要说清的取舍：日历行是**流之外的全宽行**，与块不在同一个顺序表里——给它 ↑↓ 两个点不动的箭头比不给更坏（[26](26-home-widgets-and-settings.md) §实际交付 10 已记），所以**只给开关、不给排序**；等 §4 落地后它进了流，再把排序补上。

## 6. 备选（都更便宜，但都只解决一半）

| 备选 | 做法 | 解决 | 没解决 |
|---|---|---|---|
| A. 只压块内几何 | 待办环 52→40、按可用高度算行数 | P4 | P1/P2/P3 |
| B. 大块不拉伸 + 省下的高度给小组件带 | 主块带高度按内容，回调给小组件带 | P1 的一半（高度）、多一行 | **P1 的横向空**、P3 |
| C. 提高行高 96→140 | 待办不裁 | P4 | P1/P2/P3，且默认档先丢日历行 |

**推荐 §4**：只有它同时解决 P1/P2（横向空与拥挤）与 P3（日历并入组件节）；A/B/C 都可以作为 §4 落地前的临时缓解。
