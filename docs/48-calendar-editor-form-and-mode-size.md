## 一句话方案

把日历面板右栏的「新建/编辑」从**两套字段、一列排不开**改成**一个表单四种入口**（字段并排：目标+全天 / 开始+结束 / 地点+链接），删掉常驻的 5 行说明文案，把「输入即自动解析」换成**显式「生成」按钮**，并让**编辑档**单独把面板撑到 474 高（左栏让位成 260pt 的「回到月历 + 当日清单」，编辑区 = 宿主内容宽 − 260 − 12（用户当前 887 宽下 ≈ 615）× 400）。

## 背景与目标

**问题现状**（用户 2026-10-14 实测与逐条反馈）：

- 新建/编辑时「无意义的显示内容较多，这个块本身就不大」：右栏只有 (887 − 12) / 2 = **437.5pt** 宽，却常驻 `仅发送此原文及参考日期/时区…`、`使用「AI 模型」设置中的默认文字模型。`、`AI 模型设置` 按钮、状态词一行、失败时两行，外加「补充信息」这个下面只挂一个「地点」的区标题。
- **日程与待办各一套版式**（字段条数 10 / 7），换个类型就要重新找位置。
- **输入即触发 AI 解析**：停止输入 800ms 就自动解析（`CalendarSourceDebouncer`），结果会合并进正在编辑的草稿；半句话必然满足不了模型的输出契约 → 报「模型返回的日程格式无效」并阻断保存。
- **编辑区太小**：437.5 × 278，一屏看不到「链接 / 备注」，用户原话「日历编辑页面也要放大，现在操作起来很不方便」。

**预期结果**：

- 一个表单承载四种入口，差异只有 3 处且都在内容层：类型控件可点 / 锁定、生成行出现 / 不出现、时间块 2 格 / 1 格 + 地点有 / 无。
- 常驻文案 5 行 → 0 行（失败时才 1 行）。
- 生成由用户点「生成」触发（不再自动）；打字阶段不产生任何解析与草稿写入。
- 编辑档：面板 887 × **474**、左栏 260（当日清单）、编辑区 **615 × 400**（可视面积 2.0×），一屏放完。

**承接关系**：承接 docs/39 的「单草稿 + 保存前校验 + 右栏 list/detail/editor 三页」与 docs/46 的「页级文字布局/测量」；本次不改草稿模型、不改保存校验、不改会议入口（那批已在 [docs/47](47-meeting-entry-and-one-click-open.md) 完成）。**术语沿用**：`CalendarDraft` / `CalendarPanelSession` / `CalendarPanelPages` / `generationMode` / `confirmations`。

## 做法

1. **表单**（`CalendarPanelPages.editorPage`）：改成两列网格 —— 标题整宽；`目标｜全天`、`开始｜结束`（待办时只有 `截止` 一格）、`地点｜链接` 三行各两格；备注整宽；底部取消/保存。类型分段控件在**编辑时锁定**（disabled 而不是不渲染）。去掉「补充信息」区标题。
2. **文案**：删 `calendar.generation.sendingScope`、`calendar.generation.model` 两行与 `calendar.generation.settings` 按钮（降级为标题行右侧的齿轮图标）；状态词不再占一行（并入「生成」按钮的副标或只在失败时出现）；失败只保留一行「生成失败：<原因>」+ 重试。
3. **显式生成**（`CalendarPanelSession` + 视图）：输入文本放**视图本地 `@State`**，点「生成」或 ⌘↩ 才写进 `draft.sourceText` 并触发一次解析；删掉 800ms 自动调度（`CalendarSourceDebouncer` 从编辑页摘除）。`sourceRevision` / `parsingID` / 草稿合并那套过期防护**原样保留**（它们是防串稿的，不是自动解析的一部分）。
4. **编辑档尺寸**：日历页**按档各报一个自然高**（列表档 = `monthGridHeight`；编辑档 = 固定 400），沿用笔记页「列表档/编辑档两档两键」（`notesPanelTabKey(for:)`）的既有做法；编辑档左栏从整月网格换成 260pt 的「回到月历 + 当日清单」，编辑区因此拿到 615 × 400。

## 备选与取舍

| 备选 | 为什么不选 |
|---|---|
| 保留自动解析、只把延时拉长 | 用户要的是「输完再生成」；半句话的解析结果必然是废的（模型输出契约要求 12 个键齐 + 合法时区） |
| 保留两套版式、只做视觉对齐 | 用户明确「不能出现两种」 |
| 编辑档左栏整栏隐藏（编辑区吃满 875） | 会丢掉月份上下文；收成 260pt 的当日清单既省宽度又保住「回到月历」 |
| 编辑档高度由内容决定 | 在备注里打字会让面板一直长高；必须固定声明（与 docs/30 §做法 机制六 同口径） |
| `.scaleEffect` 缩放整个面板 | 文字会糊、控件失真（用户已接受的放大方案另见设计图 ⑦⑧，本次不做） |

## 明确不做

- **整体面板放大与「内容缩放」倍数**（设计图 ⑥⑦⑧⑨）：用户 2026-10-14 明确「先不考虑放大的问题了」。本次**只**让编辑档这一页的自然高报到 400（→ 面板 474；这是设计图 ⑤ 交付的前提），列表档与其它的尺寸一个都不动。
- **面板尺寸变化的丝滑过渡**（设计图 ⑧）：一并搁置；编辑档切换沿用既有的单步缓动。
- 不改会议入口（docs/47 已完成）、不改草稿模型字段、不改保存校验规则、不改列表/详情档的版式。
- 保留 `CalendarSourceDebouncer` 类本身（其它调用点/测试可能仍用），只从编辑页摘除自动调度。

## 已知限制

- 编辑档 474 只在**编辑**时生效；列表档仍是 352，切档时面板高会变（与既有「翻月面板高会变」同类）。
- 编辑档左栏的「当日清单」是只读摘要（回到月历 + 选中日 + 该日日程条），**不**在里面编辑。
- 备注写长了仍会滚动（两列布局只是让**典型内容**一屏放完，不是把备注钉死）。
- 显式生成之后，「生成」按钮在草稿已就绪时仍可再点（重新生成），与失败重试共用同一个入口。

## 验收标准

- 单元测试：显式生成（打字不解析、点生成才解析）、两列布局的字段数/并排关系、类型控件编辑时锁定、编辑档页键与自然高 400、列表档 278 不变。
- Release 构建通过；用户上屏复核：新建/编辑四种入口同一个版式、编辑档一屏放完。
