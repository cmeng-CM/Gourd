## 一句话方案

把这一轮的四件事一次做掉：① **修掉生成失败**（解析层读不懂「三点半」，模型照约定引用原文反而被判无效）；② **待办表单**收掉两处空半格（`截止｜链接` 并一行）、备注给可见落点、原文区默认收到 3 行；③ **生成区三态按钮常驻**（失败时不再没有按钮）；④ **字号 +3 号**（编辑页与列表卡片），并把列表行改成**整行点开详情浮层** + 行内 **编辑 / 删除**（详情页退休）。

## 背景与目标

**问题现状**（用户 2026-10-15 实测与反馈，逐条带证据）：

1. **生成直接失败**：用户输入「精准维修云平台周会，今天下午三点半，会议时长一个点」，点「生成」→ 失败「无法根据原文验证生成的日程」。
   根因（用真实解析器 + 测试桩实测，见「做法 1」）：`clockEvidence` 只认 `H:mm` 与「X点」两种写法，而同一个文件里的 `timePattern` 认「X点半 / X点Y分」——**认得出、却解不开**；prompt 又要求模型逐字引用原文，于是越合规越必失败（同一句把证据改成「下午三点」就通过；原文写「15:30」也通过）。
   第二处：原文只有「时长」这类说法时，模型一旦据此推出结束时间（16:30），`endEvidence` 填什么都不合法（填「会议时长一个点」不是钟点、填「16:30」原文里没有）；模型若**不推**结束时间反而能过（应用自己有「起点明确且无结束提示时默认一小时」）。
2. **待办表单两处空半格 + 备注被挤出**：两列网格为列对齐留了两个空半格（「截止日期」右边、「链接」左边，`Color.clear`），用户圈出的就是后者；同时表单内容总高 **436pt**（实测）> 编辑区 **400pt**，备注只剩标签露在滚动区底沿。
3. **失败后没有生成按钮**：失败态把主按钮从工具栏排除，只在失败行放了两个纯文字按钮（`重新生成` / `改为手工填写`），看不出能点。
4. **字号太小**：编辑页 标签 `.caption`=**10pt**、输入框正文 **12pt**、日期控件 **11pt**、大文本编辑器 **13pt**；而列表卡片标题是 13pt——同一屏里两个尺度。
5. **只能点小箭头进详情**：列表行右端的 `›` 命中区约 20 × 20pt；「编辑 / 删除」只在详情页里，且只对可写日程出现；待办行连详情页都没有这两个入口。

**预期结果**：

- 用户原文（含「X点半」「X点Y分」）能被正常解析；只有时长时由应用自己补「一小时」而不是失败。
- 待办表单无空半格、备注有可见落点；编辑档 400pt 内一屏放完——+3 号后内容高约 410pt，靠**不改尺寸**地把行距从 10 收到 8 守住 ≤400。
- 生成按钮在任何状态下都在同一格、一眼看得出是按钮。
- 编辑页字号 13 / 15 / 13 / 16，列表卡片 15 / 13，两页一致。
- 列表行整行可点（弹详情浮层），行内直接给 ✎ / 🗑（可写日程给两个、待办只给删除）；删除就地确认。

**关键约束**：不动整体尺寸（编辑档自然高仍 400）；不改会议入口（docs/47）；不改草稿模型与保存校验规则；详情浮层必须是**面板内自绘**（非激活 NSPanel 里 NSPopover 撑不住，本项目实测过）。

**承接关系**：承接 docs/48 的表单与按档自然高（编辑档 400 / `calendarPanelTabKey`），本次只在其内部收口；承接 docs/39 的「单草稿 + 保存前校验」，草稿机制一字不动。

## 做法

1. **解析层修生成失败**（`ScheduleParsing`）：给 `clockEvidence` 补「X点半」「X点Y分」两支，并用一条不变量把它和 `timePattern` 绑在一起（**凡是 `timePattern` 能匹配且含义规范的词形（时 0–23、分 0–59），`clockEvidence` 都必须解得开，含 `零X` 读法如 `三点零五分` → 03:05；越界取值与畸形写法（`十零`/`一十`/`零十`/`零零五`）按原路径确定性拒绝**——现测试里一个「点半」样例都没有，这个分叉就是这么长出来的）；prompt 侧把「只有原文出现钟点时才给 `end`（否则 `end` 与 `endEvidence` 都留空）」写死，让时长类说法落回应用既有的「默认一小时」。
2. **表单收口**（`CalendarPanelPages.editorPage`）：待办把「截止」与「链接」并成一行（各占半格，两处 `Color.clear` 占位删除；日程的「开始｜结束」「地点｜链接」两行不动）；备注给浅边框与占位文字（**占位复用既有 `calendar.panel.notes` 键**，与「链接」字段同款，不新增本地化键）；`CalendarSourceGeneration` 的原文区默认收高到 3 行（内容更多时框内滚动）；+3 号后若内容高超过 400，允许在**不改尺寸**的前提下把行距从 10 收到 8 腾出 ≤12pt。
3. **生成区三态**：主按钮常驻同一格（同一 x、76 × 26pt），文案随状态换「生成 / 取消 / 重新生成」；外观改成白 14% 圆角胶囊 + 白字；失败行只留「一行红字 + 改为手工填写」。
4. **字号 +3 号**：编辑页标签 13 / 输入框 15 / 日期控件 13（`controlSize` small→regular）/ 大文本编辑器 16 / 按钮与状态文字 13；列表卡片标题 15、次要 13。
5. **列表行操作与详情浮层**：整行可点（含文字上单击）→ 钉住详情浮层；行内右端常显 ✎（可写日程）与 🗑（可写日程 + 可删待办），**这一组整组贴右**（最后一枚右缘贴行内边距内缘、间距 8、图标 16pt，右端不留空档），会议两键同类时并入这一组（最多四枚）；删除走面板内就地确认；会议行的「打开 / 复制」两键**保持原位**（D-14，不进浮层）；浮层复用既有 `CalendarEventDetailsModel` + `CalendarEventDetailsOverlay` + `CalendarEventDetailCard`（**这三件目前在运行期没有宿主**，本次重新接线）。
6. **详情页退休**：`CalendarPanelRoute.detail` 与其页面、返回按钮、`showDetail`、anchor 恢复一并删除，内容（打开系统日历 / 只读原因）并入浮层卡片底部。
7. **首页「今日」条目也弹同一个浮窗**（用户 2026-10-15 明确）：点今日带的条目 → **就地弹浮窗**（不再切到日历模块、不再进详情页）；浮窗内部功能与日历面板**完全一致**（同一份 `CalendarEventDetailCard`：打开系统日历 / 完成 / 会议动作 / 编辑 / 删除）。
8. **列表档分栏改为 40 / 60**（用户 2026-10-15 确认）：左栏（月历）= 内容宽 × 40%（关系式，不写死），右栏拿其余；高度不动。

## 备选与取舍

| 备选 | 为什么不选 |
|---|---|
| 生成失败只改 prompt（让模型别引用带「半」的片段） | 把缺陷推给模型，且「三点半」是最自然的写法；同一文件里 `timePattern` 已经认它 |
| 放宽校验：证据只要在原文里出现即可，不必是钟点 | 会失去「证据确定性」的意义——那条校验正是防模型编时间的 |
| 时长由校验层自己解析（认「时长N小时/N个点」并推 end） | 要新增时长语法与确认语义，超出本次范围；本次走「不推 end + 默认一小时」（已实测通过） |
| 详情用 `NSPopover` | 面板是非激活 `NSPanel`，实测 popover 在它里面撑不住（p13 镜子那次踩过） |
| 详情用 sheet / 独立窗口 | 抢焦点，打断正在进行的输入；也与「面板内自绘」的既有口径不一致 |
| 待办行也做「编辑」 | 岛内编辑提醒是新能力（字段范围、写回 API、与系统「提醒事项」的分工），用户已拍板本批**只给删除** |
| 字号放 +2 号换「绝不滚动」 | 用户明确要「三个号」；+3 号实测只涨 26pt，配表单收口后 ≈410pt，差 10pt 可接受 |
| 保留详情页与浮层两套 | 两套看详情的方式会让人困惑；用户已选「点击＝弹详情」 |

## 明确不做

- **岛内编辑提醒**（`beginEdit` 支持 reminder + 保存路径 + 系统「提醒事项」分工）：用户拍板另开小批次。
- **整体尺寸**：编辑档自然高仍 400，面板宽度与手动/自适应口径不动。
- **月历网格字号**：那是 `MonthGridLayout` 派生的一套（已 ×1.2），本次不动。
- **会议识别 / 会议入口**（docs/47 已收尾）、草稿模型与保存校验规则。
- 面板尺寸变化的丝滑过渡（仍是搁置项）。

## 已知限制

（起草：终审回写时按实际实现补齐，至少覆盖以下几条）

- **编辑档的可视区只有 336pt**（400 − 表头 30 − 底部动作 34），不是 400——表单能用到的高度是这一块。实测：13 号下新建待办 331（放得下）、新建日程 374（超 38）；**+3 号后新建待办 371（超 35）、新建日程 420（超 84）**，只有编辑既有日程（325）放得下。本轮按计划口径（内容 ≤ 400）判定不回归，差额打印进用例输出（`校准读数：…`），**编辑档高度是否抬（400 → 500 左右）留待用户拍板**——它是用户可见尺寸，本轮没有擅自改。
- 「点击整行弹详情」与「按住拖动选文字」的区分依赖 `NSTextView` 的命中判定：结构上整行已挂 `onTapGesture`，**文字上的单击是否同时触发（D-22）要上屏实测**；自动化只判非文字区域与结构。
- 待办行本批只给删除，仍不能在岛内编辑（指南口径不变）。
- 分栏 40% 后 3 字节日名（「重阳节」门槛 ≈54.8）对格宽 56.1 只剩 ≈1.3pt 余量——字体度量一变就会翻，属贴边风险（4 字口径见下条）。
- 分栏 40% 后日格宽 71.6 → 56.1：按 D-21，**初一那格改为只显示月名**（「九月」2 字，门槛 44 ≤ 56.1），其余日子仍是 2 字日名。想连「九月初一」（4 字，门槛 65.7）一起保住需取 47 / 53（右栏只 +85pt）。
- 环境带（D-24）：列数上限取 24 → 面板宽超过 ≈1250pt 时，前台应用块的余量又会露白（24 × 28 = 672pt 用满为止）；再宽要么继续抬上限、要么把余量分给别人。
- 浮窗的收起（D-23）：鼠标移出面板即收起，浮窗随之关闭——浮窗**不是**"钉住就锁住面板"的形态；面板内的点击不受影响。
- 「文字上单击也弹浮窗」（D-22）与文本拖动选择的区分需要在 `NSTextView` 的命中判定里实现；若实测无法两全，先回报再定（不许默默只留一种）。
- 待办删除（T5 新增链路）：服务层原本只有 `deleteEvent`（吃 `EKEvent`），提醒删除是**本轮补的** `deleteReminder`；若将来有别的宿主只注入了 `deleteEvent`，那里删待办会返回 false（不做静默降级）。
- 面板列表行满配时右端最多 3 个图标（会议 22 + ✎ 28 + 🗑 28 + 2×8 = 94pt），标题按剩余宽度截断（D-19）；「平台名 + 会议号」仍是文字信息。
- 解析层支持集合之外的词形（如「三点三刻半」）仍确定性拒绝；中文数词的分钟要认 0–59（「三点十五分」这类必须能用，否则等于没修）。
- 首页「今日」条目按 D-15 要就地弹同一个浮窗——**T7 未做**，今天仍走旧的「切到日历模块 + 进详情页」路径（`TodosModule.swift` 的 `showDetail`）。
- 浮窗不抑制自动收起（D-23）：鼠标移出面板 → 面板照常收起、浮窗随之关闭；出口是 × / 再点同一行 / Esc / 切页 / 收起面板（四处都在 T5 接好了）。

## 验收标准

- 单元测试：解析层按用户原文与三种模型输出（合规引用 / 归一化证据 / 不推 end）都能得到预期结果；表单字段数与并排关系；生成区三态按钮同一格；字号常量；列表行命中与按钮可见性判据；浮层钉住与标志同步（含悬空复位）。
- `python3 -m unittest tests.test_general_ai_configuration` 退出码 0（本地化键增删同批）。
- Release 构建通过；用户上屏复核：生成不再失败、编辑页一屏放完、列表整行点开浮层、行内编辑/删除可用、首页今日条目也弹浮窗、分栏观感（40/60）。
