## 一句话方案

日历页每个日格右下角的「事件点」**分色**：**橙色 = 你建的日程**、**蓝色 = 节假日/农历节气那类订阅日历的条目**（颜色与位置都不变）；并在**日格右上角加一个橙色数字角标**，写当天**你的日程数量**（1–9 直显，≥10 显 `9+`）。

## 背景与目标

**问题现状**：日格右下角那枚 5pt 小圆点只有一个含义——「这天有事件」，而且**一律是主题蓝**。用户同时订了系统日历（节假日、农历节气）和自建日程，于是两类条目画出一模一样的蓝点，**分不出哪些是自己安排的**（用户 2026-10-12 截图原话：「无论是我建的日程还是节假日都显示蓝色的点，分不出来」）。另外「这天有几个我的日程」现在也完全看不出来（一天画一枚点，多与少同形）。

**预期结果**：一眼能分色（橙＝我的、蓝＝节假日/节气），且右上角角标直接给出我的日程数量。设计稿见 §关联来源。

**关键约束**：**不改日格几何**（日格仍 36pt 高、`monthGridHeight` 仍 `43N + 63`）——角标与点都画在格内叠加层，一行网格的高度算式一个字不动（p15 的整点几何与「网格底贴住行底」结构护栏必须继续成立）。**不改日历页三页面结构与交互**；节假日/农历节气**继续接系统日历**（不引入内置节日表做判据）。

## 做法

**① 分类判据 = 事件所属日历的可写性**（不猜日历标题、不按日期猜、不加设置项）：

- **信息类（蓝）** = 事件来自**订阅或只读**日历（`CalendarModel.isSubscribed` 或 `!allowsContentModifications`）——节假日、农历节气这类系统日历正是这一类；
- **我的（橙）** = 事件来自**可写**日历。

这条判据与项目既有的「只读日历不在岛内改删、转系统维护」是**同一条边界**（docs/39 D-03），所以「能改的是我的、不能改的是信息」在语义上也自洽。

**② 日格上画三样**（都在格内叠加，不改几何）：

- 右下角**点**：我的日程 > 0 → 橙点在最里侧；信息类事件 → 蓝点。两者都有时并排（橙在左、蓝在右，间距 2pt）。
- 右上角**角标**：橙色实心圆（直径 14pt，`(12 × scale).rounded()`），内写当天**我的日程数**（深色数字）；1–9 直显数字，≥10 显 `9+`（两字符，字号从 9 降到 7 那档）。当天没有我的日程（`mine == 0`）就不画。
- 农历/节气/节日**副标文字保持不变**，不参与分色。

**③ 聚合是纯函数**：把「某天有我的日程吗／有几条／有信息类条目吗」抽成不依赖 SwiftUI 的纯函数（输入当天的 `[EventModel]`，输出一个小结构），单测直接钉分类、计数与 `9+` 档。

## 备选与取舍

| 选择 | 理由 |
|---|---|
| 按**日历标题关键词**（「节假日」「农历」）判信息类 | 不选：靠名字猜，用户改个日历名就失效 |
| 按**日期是不是节假日**（用 App 内置节假日表判）判 | 不选：用户明确「节假日、农历节气现在是接系统日历，还维持就行」——引入第二套判据会和系统日历的条目对不上 |
| 把点做成「一天画 N 枚」（点数即数量） | 不选：用户选了变体 A（点分色 + 右上角数字角标）；点数在多日程时会挤爆日格 |
| 角标放右下角、与点同一排 | 不选：右下角同时要点与数字，两个 5pt 点 + 数字在 56pt 宽的格子里会挤成一团；右上角是格内唯一的空位（设计稿已按此出图） |
| 给角标加开关（显示/隐藏） | 不选：本轮按用户要求直接上；设置项以后真有需要再加 |

## 接口与数据形状

```swift
// components/Calendar/DynamicIslandCalendar.swift —— 新增纯函数（无 SwiftUI 依赖，单测直接钉）
struct MonthDayEventMarks: Equatable {
    let mine: Int      // 我的（可写日历）事件数
    let hasInfo: Bool  // 是否有信息类（订阅 / 只读日历）事件
}
enum MonthDayEventMarksBuilder {
    static func marks(for day: Date, events: [EventModel], calendar: Calendar = .gourdDisplay) -> MonthDayEventMarks
    /// 归类判据（唯一一处）：可写 → 我的；订阅或不允许改 → 信息类
    static func isInformational(_ calendar: CalendarModel) -> Bool
    /// 角标文案：0 → nil（不画）、1–9 直显、≥10 显 "9+"（纯函数，单测钉边界）
    static func badgeLabel(count: Int) -> String?
}
```

**按天聚合的区间**：`marks(for:…)` 用与既有 `MonthGridLayout.daysWithEvents` **同一条规则**切天——一条事件覆盖 `[startOfDay(start), startOfDay(end − 1s)]`（那个 −1s 是全天事件 `end` 为次日零点排他值的处置）；零长 / 数据异常（`end ≤ start`）时退化为只覆盖起始日。落在这一天的事件再按 `isInformational` 分两堆：可写的累加进 `mine`、订阅 / 只读的置位 `hasInfo`。

```swift
// MonthGridLayout —— 新增刻度（由 scale 派生后取整，都是整点；本仓 scale = 1.2；不改任何既有常量）
static let badgeDiameter: CGFloat = (12 * scale).rounded()          // = 14 —— 右上角角标直径
```

## 已知限制

- 实装后定稿（起草期先列，实现期踩到的已补入）：
  - **判据是「可写性」而非「是不是节假日」**：订阅或只读日历的条目一律算信息类（蓝）。副作用：**别人共享给你的只读日历**也会是蓝点——与「不能改的就不是我的」这条口径一致，但如果你希望它算「我的」，得改判据（或加回溯设置）。
  - **角标只数「我的」**：节假日那天的信息类条目不计入数量。
  - **一天多枚点不逐枚画**：我的日程不论几条都只画一枚橙点（数量交给角标）；信息类同理只画一枚蓝点。
  - **补格（跨月）沿用既有的 45% 降档**：不属于当前显示月份的日格，橙点、蓝点与角标一律降到 45% 不透明度——这是蓝点改前就有的口径，只是本轮把橙点与角标一并纳入；日号本身在补格是最低档（`outOfMonthOpacity`），标记跟着弱化，免得把视线引到非当前月的日子上。
  - 角标与点在**浅色底（玻璃档）**上仍是彩色实体（橙底 + 深色数字、彩色点），不依赖白字，所以不重蹈 p18 的对比度问题；但橙点与蓝点在极亮底上仍需用户上屏复核观感（见 §实际交付 遗留项）。

## 验收标准

- 日格右下角：有我的日程 → 橙点；有订阅/只读日历条目 → 蓝点；两者都有 → 并排两枚（橙左蓝右，间距 2pt）。
- 日格右上角：有我的日程时出现橙色角标，数字 = 当天我的日程数（1–9 直显，≥10 显 `9+`）；没有则不画。
- 副标文字（农历/节气/节日）与今天完全一致；日格高、行高与网格结构护栏的所有既有断言不变（`monthGridHeight` 仍 `43N + 63`）。
- 纯函数单测：分类（可写 → 我的；订阅 → 信息；只读 → 信息；一天多条累加）、`badgeLabel` 的 0/1/9/10/99 边界、跨日与全天条目归到正确的天。
- Release 构建通过；上屏复核（需用户）。
